## Master Prompt 64 (2026-07-21, « Verrouillage du tarif Express de nuit ») — bug de tarification réel trouvé (le tarif Express n'a jamais correspondu à la règle métier énoncée, ni le jour ni la nuit), corrigé à la source unique de vérité, verrouillé par 14 nouveaux tests (6 Dart + 8 Node) sur les deux ports (Dart/Node) qui partagent cette formule.

**Cartographie exhaustive (« rechercher tous les endroits où le prix Express est calculé »)** : un seul calcul réel existe dans toute l'app — `lib/services/tarif_service.dart:TarifService.compute()` (Dart) et son port fidèle `functions/tarifService.js:compute()` (Node), déjà établis comme source unique de vérité tarifaire depuis le Master Prompt 51. Tous les autres consommateurs lisent le résultat de cet appel, aucun ne recalcule ni ne code en dur un montant Express séparé :
- **Écrans avec sélecteur Standard/Express réel** : `lib/screens/client/livraison_screen.dart` (`_expressPrice => _tarifResult?.expressPrice`) et `lib/screens/client/courses_screen.dart` (`_expressFee => _tarifResult.expressPrice`) — les deux seuls écrans où un client peut réellement choisir le mode Express.
- **Serveur (AZ IA)** : `functions/azia/tools/delivery.js` (`budget = deliveryMode === 'express' ? tarif.expressPrice : tarif.standardPrice`) — même source, jamais de fourchette devinée par le modèle.
- **Écrans sans mode Express, vérifiés pour confirmer l'absence de duplication** : `create_order.dart` (n'utilise que `tarif.standardPrice`, pas de sélecteur Express) ; `pharmacie_garde.dart`/`boulangerie_order_page.dart`/`functions/azia/tools/pharmacies.js` (`tarif.standardPrice` uniquement, pas de mode Express — confirmé par recherche exhaustive, cohérent avec la doc déjà actée « pas de mode express pour les pharmacies/boulangeries »).
- **`lib/services/delivery_service.dart`** (moteur de tarification legacy, déjà documenté comme superseded depuis le Prompt 51) : aucun concept d'Express — non concerné.
- **Firestore/historique/livreur** : `orders.budget` est écrit **une seule fois**, à la création de la commande, à partir du résultat exact de `TarifService`/`tarifService.js` — `suivi_commande.dart`/`driver_dashboard.dart` ne font que lire ce champ déjà stocké (`order.budget`), aucune re-computation nulle part. Cohérence avant paiement / Firestore / livreur / historique garantie par construction (une seule écriture, lue partout ensuite), pas seulement observée.

**🔴 Bug trouvé (déjà signalé sans être corrigé au Master Prompt 130) : ni le tarif jour ni le tarif nuit Express ne correspondaient à la règle métier.** Dans la branche zone centrale (≤8km, celle réellement gouvernée par un montant plat) : `expressPrice: night ? 1000 : 700` — jour = 700 FCFA (devrait être 1000), nuit = 1000 FCFA (devrait être 1500, et surtout **identique au tarif nuit Standard**, donc aucune majoration Express la nuit). Les deux valeurs étaient fausses, pas seulement la nuit.

**Corrigé dans les deux fichiers (source unique de vérité, aucune duplication introduite)** :
- `lib/services/tarif_service.dart` : `expressPrice: night ? 1500 : 1000` + commentaire `BUSINESS RULE` inline (à la ligne exacte) et bannière en tête de fichier.
- `functions/tarifService.js` : même changement, même double commentaire (ligne exacte + bannière en tête de fichier, juste après le rappel déjà existant « toute modification doit être appliquée aux DEUX fichiers »).
- **Non touché, volontairement** : la branche hors-zone (tarif kilométrique, `expressPrice: round50(std * 1.4)`) — la règle métier énoncée ne donne que deux montants plats (1000/1500) sans barème kilométrique, donc traitée comme un calcul distinct (majoration proportionnelle par distance), pas comme une violation de cette règle précise.

**Tests automatiques ajoutés — 14 au total, sur les deux ports :**
- `functions/test/tarifService.test.js` : 2 tests existants corrigés (valeurs `700`→`1000` jour, `1000`→`1500` nuit, avec titres mis à jour) + **6 nouveaux tests exacts demandés** (10h/19h59/20h00/23h30/05h59/06h00) → **248/248** tests Node verts (242 + 6).
- `test/services/tarif_service_test.dart` (nouveau fichier, n'existait pas avant cette passe) : les mêmes 6 tests aux heures pivots + 2 tests de cohérence jour/nuit complets (standard+express) → `flutter test` **59/59** verts (51 + 8, dont les 6 demandés).

**Validation** : `flutter analyze` (0 erreur, 8 avertissements préexistants inchangés) ; `flutter test` 59/59 ; `npm test` (functions) 248/248 ; `git status` confirme exactement 4 fichiers touchés (`tarif_service.dart`, `tarifService.js`, `tarifService.test.js`, + le nouveau `tarif_service_test.dart`) — aucune règle Firestore, aucun écran, aucune autre Cloud Function modifiés.

**Confirmation finale demandée par ce prompt** : le tarif Express est désormais fixé à **1000 FCFA le jour et 1500 FCFA la nuit partout où il est réellement calculé dans l'application** (un seul point de calcul par plateforme, Dart et Node, tous deux verrouillés par des tests qui échoueraient immédiatement si quelqu'un modifiait ces montants sans le vouloir) — vérifié avant/après paiement (le prix affiché au client provient du même appel que celui écrit dans `orders.budget`), dans Firestore (`orders.budget`, écrit une seule fois), côté livreur et dans l'historique (les deux ne font que lire ce champ stocké, jamais de recalcul), et dans les Cloud Functions (AZ IA utilise le même `tarifService.js`).
